# 모이다 서비스화 전면 감사

점검일: 2026-10-07

## 결론

현재 코드는 로컬 검증용 알파로는 동작하지만, 공개 다중 사용자 서비스로 바로 배포할 상태는 아니다. 출시 판단의 핵심은 기능 수보다 회의 원문 보호, 전사 실패 복구, 공급자 비용·쿼터 통제, 데이터 보존·삭제 정책이다. 특히 Deepgram 브라우저 직접 연결과 로컬 프로세스 단위 제한은 공개 서비스의 경계로 사용할 수 없다.

현재 브라우저에 저장 전 회의 문장 27개가 남아 있어, 화면 새로고침이나 현재 로드된 Vue 모듈의 HMR을 유발할 수 있는 작업은 보류했다. 이 기록을 사용자의 명시적 선택 없이 서버에 저장하거나 외부로 전송하지 않는다.

## 이번 점검에서 구현한 항목

- 회의 삭제를 V6 소프트 삭제로 구현했다. 활성 목록과 조회에서는 숨기고 휴지통에서 복구할 수 있다.
- 회의 생성자 또는 팀 소유자만 삭제·복구할 수 있고, `MEETING_TRASHED`와 `MEETING_RESTORED` 감사 이벤트를 남긴다.
- 일반 팀원은 자신이 생성했거나 직접 삭제한 회의만 휴지통에서 보고, 팀 소유자는 팀 전체 휴지통을 볼 수 있다.
- Deepgram 임시 토큰은 성공한 발급만 재시도 간격을 소비하고, 동시 발급 예약·응답 크기·본문 시간 제한·권한 재확인을 적용했다.
- 브라우저 공유 오디오 요청 모듈을 추가했다. 실제 오디오 트랙이 없거나 권한이 거절되면 자동 fallback 없이 종료하며 영상 트랙은 읽거나 전송하지 않는다.
- 공유 오디오의 audio/video track 중 하나가 끝나면 전체 캡처를 정리하고 호출자에게 한 번만 알리는 lifecycle 경계를 추가했다.
- 프런트 휴지통 API 계층을 추가했다. 현재 회의 기록을 보존한 뒤 목록·삭제 확인·복구 화면에 연결해야 한다.
- 로컬 STT와 로컬 호환 LLM 응답 본문에 총 deadline과 스트림 종료를 적용해 멈춘 공급자가 처리 슬롯을 영구 점유하지 못하게 했다.
- 남아 있는 레거시 Nuxt 모의 인증을 개발 빌드에서만 허용하고, 공개 예시 세션 비밀값을 유효한 비밀로 인정하지 않게 했다.
- 기본 `npm run preview`는 취약한 레거시 앱을 띄우지 않고 실패하도록 닫았다. 레거시 미리보기는 보안 해결 전 배포 금지 안내와 함께 명시적 `preview:legacy`로만 남겼다.
- 상세 출시 계획은 `docs/SERVICE_READINESS_PLAN.md`에 분리했다.

## P0 — 공개 서비스 차단 항목

1. **저장 전 기록 복구**: 현재 전사 문장은 저장 전까지 Vue 메모리에만 있어 브라우저 충돌·모바일 탭 퇴거 시 복구할 수 없다. 사용자·회의·기준 리비전별 변경을 IndexedDB에 저널링하고, 재진입 시 `복구 / 다운로드 / 삭제`를 선택하게 한다. 서버 자동 업로드는 하지 않는다.
2. **전사 중 이동의 명시적 종료**: 화면 이탈 시 현재 구현은 세션을 즉시 dispose하여 버퍼와 큐를 지운다. 캡처 중지와 최종 응답을 기다리는 `stopAndDrain()`을 제공하고 `저장 / 다운로드 / 처리되지 않은 음성 버리기` 중 하나를 명시적으로 선택하게 한다.
3. **요청 시간 경계**: 공통 API 요청에 타임아웃과 `AbortSignal`이 없어 저장이 영원히 대기할 수 있다. 요청별 기본·장기 제한, 취소 버튼, 타임아웃 전용 오류, 재시도 mutation의 idempotency key를 적용한다.
4. **음성 중계와 비용 경계**: Deepgram 브라우저 토큰을 서버 중계로 바꾸고 팀별 동시 연결, 분당 음성, 월 예산, 강제 종료, 공급자 장애 차단을 적용한다.
5. **분산 속도 제한**: 로그인·가입·초대 코드·음성·AI·토큰 발급을 사용자/IP/팀 단위로 제한한다. 현재 `Semaphore`와 세션 시간창은 한 JVM만 보호한다.
6. **운영 데이터베이스**: PostgreSQL, 암호화 백업, 실제 복구 훈련, 연결 풀과 마이그레이션 롤백 절차를 준비한다. 기본 H2 파일 DB는 개발 전용으로 유지한다.
7. **개인정보 수명주기**: 참석자 고지, 처리 공급자, 보존 기간, 내보내기, 삭제 요청, 계정·팀 탈퇴, 휴지통 만료와 영구 삭제 승인 절차를 제품 정책과 코드에 함께 반영한다.
8. **운영 관측**: 지연·오류율·큐·사용량만 수집하고 음성, 전사 원문, 질문, AI 답변, 키와 토큰을 로그·오류 추적에서 제거하는 필터를 검증한다.
9. **실제 음성 기준**: 거리, 잡음, 동시 발화, 한영 혼합, 숫자·날짜·부정어를 포함한 동의된 평가 세트로 정확도와 p50/p95 지연을 측정한다.
10. **레거시 배포 표면 격리**: 기본 `preview`는 fail-closed로 바꿨지만 `preview:legacy`와 루트 의존성에는 high 7건·critical 7건이 남아 있다. 강제 다운그레이드로 덮지 말고, Spring/Vue 서비스 배포물에서 레거시 서버와 의존성을 제거·별도 보관하거나 호환 가능한 수정 버전으로 전면 검증한다.
11. **저장·리비전 예산**: 계정 생성만으로 최대 500×4,000자 전사 리비전을 반복 저장할 수 있다. 팀별 총 저장량, 회의당 리비전 수, 요청 크기, 음성 초, 토큰, 월 비용을 공유 저장소에서 제한한다.
12. **영구 삭제 작업**: 현재 삭제는 복구 가능한 휴지통이며 영구 삭제가 아니다. `purge_after`와 멱등 purge 작업을 만들고 전사 리비전·문장·할 일·임시 AI 작업·메타데이터를 정책에 따라 제거한다. 감사 tombstone에는 원문을 남기지 않는다.

## P1 — 제한 베타 차단 항목

1. 휴지통 UI와 공유 탭 오디오 베타를 연결하고, 삭제 전 저장되지 않은 기록 경고·복구·권한 오류를 브라우저 E2E로 검증한다.
2. 회의 종료 조건에 요약 초안, AI 질문·답변 초안과 진행 중 요청을 포함한다. 현재 종료 함수는 전사·할 일·직접 입력만 차단한다.
3. AI 작업 ID를 재진입 시 복원하고, 일시적 poll 실패 뒤에도 제한된 backoff로 재개하며 취소 결과를 확인한다.
4. mutation 성공 뒤 보조 목록 새로고침이 실패해도 성공을 실패로 되돌리지 않는다. 현재 할 일 생성과 전사 저장은 이 경계가 섞여 중복 생성이나 거짓 실패를 만들 수 있다.
5. 초기 회의·전사·멤버·이력 로딩을 분리하고 기준 전사와 버전이 준비되기 전에는 캡처·저장을 비활성화한다.
6. Groq 배치 전사는 공급자 응답이 캡처 속도보다 느리면 직렬 큐가 결국 포화된다. 큐 예산, 남은 음성 처리 상태, 세션 재시작 안내와 장시간 회의 부하 테스트가 필요하다.
7. Deepgram의 `is_final`과 `speech_final`, 연결 세대, 늦은 응답, 중복, 공유 중단, 네트워크 복귀를 하나의 상태 처리기로 검증한다.
8. CSP, Permissions-Policy, HTTPS 전용 쿠키, 신뢰 프록시 범위와 세션 만료 UX를 실제 배포 경로에서 검증한다.
9. 가입→팀→회의→가짜 음성→수정→저장→종료→삭제→복구 흐름을 Playwright 등의 E2E로 자동화한다.
10. 팀원 제거, 초대 코드 회전·만료·폐기, 소유권 이전을 추가하고 권한 회수 시 음성 연결과 대기 작업도 종료한다.
11. 회의 종료·전사 리비전·할 일 변경 권한을 `owner/editor/viewer`로 명시한다. 현재 일반 팀원도 다른 사용자의 회의를 종료하거나 정본 전사를 바꿀 수 있다.
12. 외부 공급자 전송에는 원문 없는 공개 이력(actor, provider, purpose, data category, 정책 버전, request id, 시각, 결과)을 남긴다.
13. 개발 기본값을 명시적 `dev` profile로 옮기고, 기본/운영 시작은 PostgreSQL·secure cookie·필수 비밀값이 없으면 실패하게 한다.

## P2 — 정식 출시 품질

- 전사 문장 삭제·실행 취소·병합·분할과 수정 이력을 제공한다.
- 할 일·결정, 지식 문서·상자·에이전트에도 일관된 수정·휴지통·복구·영구 삭제 정책을 적용한다.
- 44px 조작 영역, 키보드 순서, 포커스, 200% 확대, 모바일 레이아웃, 스크린리더 상태 안내를 자동·수동으로 검증한다.
- 데이터 내보내기, 계정 탈퇴, 팀 소유권 이전과 법적 보존 예외를 운영 도구까지 포함해 구현한다.
- 외부 LLM에는 영구 문장 UUID와 정확한 시각 대신 요청 단위 인용 키와 과업에 필요한 최소 메타데이터만 전송한다.
- macOS 전체 시스템 오디오가 핵심 요구가 되면 ScreenCaptureKit 기반 서명된 보조 앱을 별도 제품 경계로 검토한다.

## 안전한 다음 순서

1. 현재 열린 회의의 저장 전 기록을 사용자가 `기록 저장` 또는 로컬 다운로드로 보존한다.
2. 개발 서버를 재시작해 V6를 적용하고, 기존 회의 조회와 신규 삭제·복구를 스모크 테스트한다.
3. 휴지통·공유 탭 오디오 UI를 연결하고 브라우저 E2E를 추가한다.
4. 서버 중계·분산 제한·PostgreSQL·백업·로그 필터를 구성한 제한 베타 환경을 만든다.
5. 실제 회의 평가 기준을 통과한 공급자와 설정만 기본값으로 승격한다.
