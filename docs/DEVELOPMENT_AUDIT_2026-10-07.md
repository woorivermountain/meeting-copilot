# 개발 요구사항 대조 및 1차 구현 결과

작성일: 2026-10-07

## 범위와 판단 기준

대상 저장소는 `woorivermountain/meeting-copilot`이다. 사용자가 제공한 2026-10-07 개발 요구사항과 실제 코드의 차이를 확인하고, 부서 자료함 확장을 독립적인 개발 단위로 추가했다. 문서의 희망 기능을 기존 구현으로 간주하지 않았다. 아래 상태는 사내 운영 인증이나 실사용 효과 검증을 의미하지 않는다.

## 이번에 추가한 수직 기능

1. `/knowledge`: 자료 테이블, 원문 확인, 검토 후 등록·삭제, 부서 자료함 생성.
2. 에이전트 이름·담당 부서·접근 자료함 지정, 최대 5개 에이전트에 공통 질의.
3. 승인 문서만 청크 검색. 에이전트의 자료함 범위와 사용자의 팀 권한을 서버에서 적용.
4. 답변별 원문 인용·문서 버전·문자 위치 표시. 근거 부족, 모델 오류, 원문 검색 모드 구분.
5. 팀 소유자만 변경 가능. 자료 등록·삭제·에이전트 배정과 감사 메타데이터를 같은 트랜잭션에서 기록.
6. 모델은 읽기 전용이다. SQL 실행, 웹 접근, 외부 업무 수행, 자동 합의·자동 저장 도구를 제공하지 않는다.

## 검증의 범위

- 기존 20개 단위·fixture 테스트에 자료함 테스트 14개 추가.
- 일회용 로컬 PostgreSQL에서 실제 마이그레이션과 통합 테스트 6개 실행: 승인 자료 저장·팀원 읽기, 타 팀 접근 차단, 비소유자 변경 차단, 타 팀 자료함 연결 차단, 배정·감사 기록, 자료 삭제.
- 타입 검사 및 프로덕션 빌드 실행.
- 데스크톱 1440px, 모바일 390px에서 실제 API를 통한 2개 에이전트 응답 표시와 가로 넘침 확인.
- 브라우저 시나리오에서 자료 등록 전 승인 필수, 등록·삭제, 근거 클릭 후 원문으로 포커스·스크롤 이동, 검색 근거 없음 상태 확인.
- 실제 쿠키 인증 API에서 미인증 401, 타 팀 조회/질의 403, 승인 없는 등록 400, 클라이언트가 위조한 자료를 무시하고 서버 자료로 답변함을 확인. DB 자료함 생성 후 새 자료함 선택도 확인.
- 실제 LLM API를 호출하지 않았다. 프롬프트 인젝션 저항성, 의미적 근거성, 지연·비용·사용자 효익은 검증되지 않았다.

보안 의존성 확인에서는 기존 트리에 `npm audit` 경고 14개(high 7, critical 7)가 반환되었다. 전이 의존성 합산이며 독립 취약점 14개나 운영 악용 가능성 14개라는 뜻은 아니다. `simple-git`, `@simple-git/argv-parser`, `node-forge`, `braces` 등이 포함된다. 자동 수정 제안에 Nuxt 다운그레이드/메이저 변경이 포함되어 그대로 실행하지 않았다. 실제 노출 경로와 호환 패치를 검토하기 전 운영 배포하지 않는다.

## 다음 개발 순서

### P0-A — 회의 산출물의 증거 계약

결정·할 일마다 evidence와 draft/approved/rejected를 도입한다. 참석자 명단 일치와 실제 책임 배정의 근거는 별도로 검증한다. 날짜는 원문 인용 및 기준 시각이 확인된 경우에만 정규화하며, 미정은 null로 유지한다.

### P0-B — 동의 기반 보존과 승인 추적

원문 미저장 모드와 승인 후 원문 보존 모드를 분리한다. 보존 목적·기간·접근 범위·삭제 정책을 확인하는 UI를 먼저 마련하고 원문, 초안, 수정 사유, 승인본, 작성자·시각을 버전 단위로 연결한다. 부서 자료함의 감사 로그는 회의 승인 이력을 대체하지 않는다.

### P0-C — 실제 팀 회의 흐름

로그인·팀 선택 UI, 실제 meetingId 생성, 참석자 입력, 회의 이력·승인본 조회를 연결한다. 이후 팀원 확인과 이견 표시를 구현한다.

### P1 — 사내 지식 및 부서간 검토

부서·문서별 ACL, 문서 버전 변경/철회, 보존기간, SSO, 요청 제한을 먼저 구현한다. 이후 파일 파싱과 임베딩/벡터 검색을 평가한다. 검색 재현율과 권한 필터를 검증한 뒤 부서별 의견 차이 요약·반론 라운드를 추가한다. 최종 합의와 업무 실행은 사람 승인으로 유지한다.

## 운영 사용 전 필수 조건

현재 팀 전체 공유 범위에서 인사·재무·고객 비밀 자료를 시험하지 않는다. 공급자의 데이터 처리 조건을 확인하고 외부 모델 전송을 승인해야 한다. 운영 DB의 서비스 계정은 최소 권한으로 구성해야 하며 테이블을 브라우저에서 직접 조회하지 않는다. 실제 고객 데이터의 마이그레이션, 외부 LLM 사용, 운영 배포는 이번 작업에 포함하지 않았다.
