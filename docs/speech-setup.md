# 마이크 입력과 전사 연결

현재 전사는 선택한 `getUserMedia` 스트림을 16kHz 모노 WAV로 변환하고, 최대 약 4초 단위로 인증된 Spring 서버에 전달해요. 발화 후 약 600ms의 정적을 감지하면 먼저 조각을 닫아요. 요청 시작 간격은 최소 4초이며 직렬 처리하므로, 대기 및 서버 처리 시간이 추가돼요. 입력 미터와 전사에 같은 스트림을 사용해요. 최대 대기열은 3개 조각이며 처리 지연이 누적되면 오류를 표시하고 중단해요. 중지하면 마지막 조각 처리를 기다리고, 화면을 떠나면 요청을 취소해요. 단어 단위 스트리밍이나 화자 자동 구분 기능은 아니에요. 조각 경계에서 문장 정확도가 떨어질 수 있어요.

마이크 설정에서 잡음 억제·울림 감소를 요청할 수 있어요. 실제 적용 여부는 장치 설정으로 확인하며, 브라우저가 값을 제공하지 않으면 확인 불가로 표시해요. 마이크 테스트는 외부로 전송하지 않아요. 오류로 중단된 미처리 음성은 복구되지 않으므로, 안내를 확인하고 다시 시작하거나 직접 입력해 주세요. 자동 재전송이나 공급자 전환은 하지 않아요.

## 품질 비교와 진단

기본 4초 모드 외에 최대 8초의 문맥 유지 비교 모드를 선택할 수 있어요. 두 모드 모두 약 600ms의 쉼에서 먼저 분할해요. 긴 구간은 연속 발화 중 강제 분할 횟수를 줄이지만 표시 대기가 늘어나며 정확도 향상을 보장하지 않아요.

`전사 상태 확인`은 최근 성공 응답의 음성 길이, 분할 이유, 전송 대기, 요청 응답 시간(네트워크 포함), 대기열, RMS, 포화 샘플 비율과 빈 응답 여부를 표시해요. 최근 20개 지표만 탭 메모리에 유지하며 음성·원문은 진단에 포함하지 않아요. 무음으로 건너뛴 구간과 실패 요청은 이 성공 응답 지표에 포함되지 않아요. 입력 경고는 경험적 기준이지 신호 대 잡음비나 인식 정확도 측정이 아니에요.

참석자 동의를 받은 동일 발화로 4초/8초 및 잡음 억제 켜짐/꺼짐을 하나씩 비교하세요. 모델 비교는 별도 승인 후 동일 음성으로 진행해야 하며, 이 진단 기능이 자동으로 모델을 교체하거나 원문을 LLM에 전달하지 않아요.

## 현재 준비 상태

2026-10-07 확인 당시 이 컴퓨터의 PATH에 whisper-cli/whisper-server/ffmpeg가 없고, Python의 whisper/faster_whisper/mlx_whisper 패키지도 없어요. 모델 설치나 다운로드는 실행하지 않았어요. 서버가 없으면 설정 화면에서 준비되지 않았다고 표시하며 전사 시작을 막아요. 실제 마이크 녹음과 실제 모델 품질 검증은 실행하지 않았어요.

## 선택 가능한 연결

- 로컬: whisper.cpp의 whisper-server를 별도로 준비해 `127.0.0.1:8178`에 바인딩해요. 한국어는 multilingual 모델이 필요해요. Spring 환경변수 `STT_LOCAL_URL`로 loopback 주소만 바꿀 수 있어요. `/health`와 `/inference`를 사용하며 음성은 애플리케이션 파일/DB에 저장하지 않아요. whisper-server 자체의 로깅·임시파일 정책은 별도로 확인해 주세요.
- 브라우저: 명시적으로 선택한 경우에만 기존 SpeechRecognition을 사용해요. 운영체제 기본 마이크만 지원하며 음성이 브라우저 업체의 서비스로 전송될 수 있어요. 네트워크 오류는 마이크 권한 성공과 별개예요.
- 외부 API: 아직 연결되지 않았어요. 공급자와 전송 목적지, 비용 및 음성 전송 동의가 정해져야 구현/설정할 수 있어요. API 키를 브라우저에 넣지 마세요. 로컬 실패 시 외부로 자동 전환하지 않아요.

## API와 한계

`GET /api/teams/{team}/speech/status`는 팀 멤버에게 준비 상태를 반환해요. `POST /api/teams/{team}/speech/transcribe`는 세션 인증과 CSRF, 팀 권한을 확인하고 10초 이하 WAV만 받아요. `X-Speech-Session` UUID와 `X-Speech-Sequence` 정수가 필요해요. 응답 순서는 클라이언트에서 확인하며 자동 재전송하지 않아요. 서버 동시 추론은 최대 2개예요. 세션 헤더는 추적용이며 서버 측 영구 중복 제거는 제공하지 않아요.

공식 서버 프로토콜: [whisper.cpp server](https://github.com/ggml-org/whisper.cpp/tree/master/examples/server)
