# Meeting Copilot 개발 인수인계

2026년 10월 7일 기준. 제품명은 모이다이며, 회의 맥락을 다시 설명하는 수고와 부서 간 후속 협의 비용을 줄이는 서비스다. 현재 최우선 과제는 실제 회의에서 읽을 수 있는 정확도와 응답성을 갖춘 전사다. 이 문서를 먼저 읽고 코드를 확인한 뒤 개발을 이어간다.

## 현재 실행 상태

- 저장소: meeting-copilot, 브랜치 codex/spring-vue-service. 기존 수정·미추적 파일이 많다. 사용자 변경을 보존하며 reset이나 일괄 덮어쓰기를 하지 않는다.
- Vue 프런트 127.0.0.1:3100, Spring 서버 127.0.0.1:8081. Java 21로 루트에서 npm run dev 실행. scripts/dev-service.mjs가 .env.service를 읽는다.
- .env.service는 비밀 설정이다. 내용을 출력하거나 문서·커밋에 넣지 않는다. 파일 권한은 0600으로 좁혔다. 실제 키 이름은 GROQ_API_KEY, DEEPSEEK_API_KEY, DEEPGRAM_API_KEY다. DEEPGRAM_도 프런트 환경에서 제외한다.
- H2 파일은 apps/server/data에 있다. 소스에는 V6 회의 휴지통 migration이 추가됐지만 현재 실행 중인 Spring 프로세스는 재시작하지 않아 아직 적용하지 않았다. 실행 중 DB를 임의 삭제하거나 복사하지 않는다.
- ::1:8081을 쓰는 kubectl은 이 앱이 아니다. 종료하지 않는다. 재시작 전 미저장 회의 기록을 확인한다.
- 현재 열린 회의에는 저장 전 문장 27개가 있다. 사용자가 기록 저장 또는 로컬 다운로드를 선택하기 전에는 Vite HMR, 화면 새로고침, 프런트 재시작, Spring 재시작을 하지 않는다.

## 구현과 검증 상태

### 음성 전사

- Groq Whisper는 기본 배치 전사다. 4초 또는 비교용 8초 최대 구간, 발화 후 600ms 정적 시 조기 분할, 최소 4초 요청 간격, 직렬 처리, 제한된 대기열을 사용한다. 중간 단어 스트리밍은 아니다.
- 마이크 선택·테스트와 브라우저 잡음 억제·울림 감소 설정이 있다. 적용 여부는 실제 track 설정으로 표시한다. 마이크 테스트 음성은 외부로 보내지 않는다.
- 전사 진단은 최근 20개 성공 응답의 처리 시간·RMS·포화 비율·분할 이유를 탭 메모리에만 보관한다. 정확도나 신호 대 잡음비 지표는 아니다. 실패·무음 구간은 포함하지 않는다.
- Deepgram은 UI에서 별도 선택하는 실시간 테스트 옵션이다. Groq와 동시 전송하거나 자동 전환하지 않는다. Nova-3 / ko / interim_results=true로 연결한다. 공식 multi 지원 목록에는 한국어가 없으므로 multi가 한영 혼합을 보장한다고 말하지 않는다.
- DeepgramController는 팀 권한·CSRF·명시적 동의를 거쳐 30초 임시 토큰을 발급한다. 영구 키는 서버에만 둔다. 세션당 발급 간격 30초 제한은 있지만 조직 전체 쿼터가 아니다.
- 브라우저가 임시 bearer 토큰으로 Deepgram WebSocket에 직접 연결한다. 토큰은 팀 단위로 제한되지 않고 연결 후 만료가 연결을 종료하지 않는다. 공개 다중 사용자 서비스 이전에 서버 중계·팀별 예산·권한 회수·강제 종료를 구현해야 한다.
- Deepgram 결과는 미확정 문장을 갱신하고 확정 결과만 기록에 추가한다. 자동 재연결·음성 재전송·자동 화자 이름 식별은 없다. 중단 시 CloseStream으로 마지막 결과를 기다린다.
- StreamingTranscript.ts는 별도 공통 상태 처리 기반이며, 현 Deepgram 어댑터에 아직 통합되지 않았다. 두 구현의 중복을 정리할 것.
- 새 Deepgram Member 키로 임시 토큰 발급 HTTP 200 확인. 합성 한국어 약 3초를 실제 전송하여 중간 결과 3개와 최종 결과 1개 확인. 기준 문장: 오늘 회의에서는 금요일 출시 일정을 확인합니다. 사용자 회의 음성은 이 검증에 사용하지 않았다.
- 프런트 테스트 44개, Spring 테스트 71개, 레거시 테스트 36개 통과(조건부 6개 생략). 서비스 빌드와 서비스·레거시 타입 검사가 통과했다.
- Deepgram grant는 성공한 발급만 30초 제한을 소비하고, 동시 발급 예약·본문 시간/크기 제한·권한 재확인을 적용했다. 성공·실패 재시도·권한 회수·stalled body 테스트가 있다.
- 공유 탭 오디오 요청 모듈은 실제 audio track을 검증하고, 권한 거절·오디오 없음에서 자동 마이크 fallback 없이 실패한다. track 종료 시 전체 캡처를 정리한다. 현재 제품 UI에는 아직 연결하지 않았다.
- 로컬 STT와 로컬 호환 LLM 응답 본문에도 총 deadline을 적용했다. 브라우저 취소를 공급자 호출까지 전파하는 비동기 경계는 남아 있다.

### 회의 삭제와 서비스 감사

- V6는 `deleted_at`, `deleted_by`를 추가한다. 활성 조회에서 삭제된 회의를 숨기고 휴지통 목록·삭제·복구 API를 제공한다.
- 회의 생성자 또는 팀 소유자만 삭제·복구하며 `MEETING_TRASHED`, `MEETING_RESTORED` 감사 이벤트를 남긴다. 프런트 API 계층은 추가했지만 화면 연결은 미저장 기록 보호 때문에 보류했다.
- 현재 삭제는 복구 가능한 휴지통이지 영구 삭제가 아니다. 보존 기간, `purge_after`, 전사·할 일·임시 작업의 멱등 purge가 필요하다.
- 서비스 웹 npm 감사는 0건이다. 루트 레거시 Nuxt 의존성은 high 7건·critical 7건이며 안전한 자동 수정 경로가 없다. 레거시를 서비스 배포물에서 제거·격리하거나 호환 가능한 수정 버전으로 검증 갱신하기 전에는 배포하지 않는다.
- 레거시 모의 인증은 개발 빌드에서만 허용하고 공개 예시 세션 비밀값은 거부한다.
- 기본 `npm run preview`는 취약한 레거시 Nuxt를 실행하지 않고 실패한다. 레거시는 명시적 `npm run preview:legacy`로만 남았으며 감사 항목 해결 전 배포하지 않는다.
- 전체 결과와 P0/P1/P2는 `docs/SERVICE_AUDIT_2026-10-07.md`, 목표 구조와 출시 순서는 `docs/SERVICE_READINESS_PLAN.md`에 있다.

### AI와 자료 접근

- LLM은 DeepSeek 연결이 있으며 이전 합성 질의가 성공했다. 전사가 LLM 응답을 기다리도록 묶지 않는다.
- MeetingAsk는 회의 스냅샷 기반 비동기 질문 처리다. 자동 질의·자동 원문 보정은 하지 않는다.
- MeetingAsk의 컨텍스트 선택은 `layered-context-v2`로 개선했다. 질문 의도, 직접 일치, 앞뒤 두 발화, 최근 발화, 결정·일정·변경 같은 회의 신호를 역할별로 묶어 전달하고 회의 제목·상태·버전도 함께 보낸다. 원문 ID 검증과 9,000자/80문장 상한은 유지한다. 단, 아직 임베딩·장기 기억·여러 회의 검색·선제 제안은 아니다.
- 자료함은 txt/md 업로드 중심이다. 같은 팀의 TEAM_SHARED 자료만 회의 답변 후보로 제공한다. 다른 팀과 PRIVATE 문서는 제외한다. 부서 이름은 표시용이며 부서별 독립 RBAC는 아직 아니다.
- useTeamDocuments 백엔드 옵션과 권한 재검증은 구현됐지만 프런트 선택 연결은 남아 있다. 검색은 제한된 어휘 기반 발췌이며 벡터 RAG라고 부르지 않는다.
- 화자 이름 저장용 백엔드 필드는 있지만 수동 이름 편집 UI와 내려받기 반영은 남아 있다. 자동 diarization도 별도 작업이다.
- 지속형 에피소드·사실 상태·하이브리드 검색·이벤트 기반 선제 제안 설계는 `docs/CONTEXT_ENGINE_DESIGN.md`에 있다.

## 다음 개발 순서

1. 사용자가 현재 열린 회의의 저장 전 문장 27개를 기록 저장 또는 로컬 다운로드로 보존한다. 그 전에는 프런트 파일 연결이나 서버 재시작을 하지 않는다.
2. Spring을 재시작해 V6를 적용하고 기존 회의 조회, 삭제, 휴지통, 복구를 스모크 테스트한다.
3. 휴지통 UI, 공유 탭 오디오 베타, IndexedDB 임시 저널, 전사 `stopAndDrain()`, API timeout/취소를 연결한다.
4. 실제 앱에서 Deepgram 선택, 동의, 토큰, 가짜 마이크, 중간 결과·종료·이탈 경고를 한 경로로 검증한다. 키와 음성 원문은 로그에 남기지 않는다.
5. 사용자가 동의한 동일 테스트 음성으로 Groq Turbo / large-v3 / Deepgram을 비교한다. 가까운 거리·실제 회의석 거리·잡음·동시 발화·한영 혼합 조건을 분리한다. 합성 음성 성공을 실제 회의 정확도로 일반화하지 않는다.
6. 첫 중간 결과 지연, 확정 지연 p50/p95, 한국어 CER 정규화 규칙, 영어 용어·숫자·날짜·부정어 보존, 누락·중복, 시간당 비용·요청 제한을 측정한다. 가격·지원 언어는 공식 문서 재확인 후 산정한다.
7. 권한 확인 후 생성한 회의 제목·안건·전문용어 참고어 초안을 사용자에게 표시하고, 전송 동의 후 STT에 전달한다. 이 기능은 계획 상태다. 이전 Groq prompt 패치는 안전 검토로 거절되어 적용되지 않았으며 이후 사용자 승인은 받았다. 전체 회의록·부서 자료 자동 외부 전송까지 승인한 것은 아니다.
8. 중간 결과 처리기를 통합하고 AudioWorklet 전환·샘플레이트 변환 품질·약한 발화 감지·잡음 처리 영향을 검증한다. VAD는 발화 감지이며 손실된 발음을 복원하지 않는다.
9. 전사 품질 확보 후 `docs/CONTEXT_ENGINE_DESIGN.md`의 P1 저장형 회의 메모리부터 구현하고, 맥락 기반 AI 액션, 자료 인용, 팀 공유 문서 검색 UI, 수동 화자 이름, 부서별 접근 제어를 연결한다.

## 혼합 발화 테스트 문장

- 이번 sprint에서는 OAuth 토큰 refresh와 API timeout을 먼저 수정해요.
- staging에서 QA를 마치고 금요일 오후 3시에 production에 배포해요.
- 응답 latency 목표는 300ms이고 p95는 1초 이내예요.
- 이 작업은 deploy하지 말고 rollback해 주세요.

철자 표기 차이와 의미 오류를 구분한다. 임시 문장 변경을 사용자가 최종 오류로 오인하지 않도록 표시한다. 영어 표기를 강제하는 LLM 후처리를 기본값으로 켜지 않는다.

## 제품과 보안 원칙

- 현재 사용 장면은 노트북 한 대의 마이크와 화면 공유다. 장기적으로 각 사용자가 로그인해 팀 권한으로 자료에 접근한다.
- 사용자 문구는 친근한 해요체, 문서 중심 UI, 최소 조작을 유지한다. 프런트 수정 시 Impeccable 스킬과 PRODUCT.md, DESIGN.md를 따른다.
- 전사 원문은 사용자 검토·승인 후 저장한다. AI 후보와 확정 기록을 구분한다. 원문을 LLM이 조용히 덮어쓰지 않는다.
- 회의 이탈·새로고침·재시작에 따른 미저장 기록 손실을 알린다. 재연결 시 미확정 발화를 복구한 것처럼 표시하지 않는다.
- 업체별 음성 전송·문맥 전송 동의와 과금 가능성을 명시한다. 다른 공급자로 자동 fallback하지 않는다.
- Deepgram mip_opt_out=true를 사용하나 이것만으로 모든 보존·계약 요건을 충족한다고 주장하지 않는다.
- 임시 토큰을 URL·로그·로컬 저장소에 넣지 않는다. 인증 확인 시 HTTP 상태만 출력한다. 키 재발급을 반복 요구하기 전에 인증 방식과 파일 로딩을 분리 점검한다.
- 자동 화자 분리는 사람 이름을 알아내는 기능이 아니다. 화자 번호와 실제 이름 매핑은 별도다.
- 테스트용 녹음은 참석자 동의·보존 기간·삭제 기준을 정한 뒤 수집한다. 현재 임의 녹음·상시 백그라운드 모니터링은 하지 않는다.
