# 모이다 트러블슈팅

로컬 Vue + Spring 서비스의 실행, 인증, DB, 전사, AI, 화면 문제를 이 문서에서 먼저 확인합니다. 설정 값이나 품질을 추측하기 전에 `서비스 → 세션 → 공급자 → 요청` 순서로 경계를 나눠 보는 것이 기본 원칙입니다.

이번 회귀 검증에서 Vue 테스트 61개, Spring 테스트 81개, Vue 타입 검사·프로덕션 빌드가 통과했습니다. 제한된 실행 환경에서는 Mockito JVM agent self-attach와 로컬 socket 생성이 차단되어 Spring 테스트가 실패했고, 같은 변경을 일반 로컬 실행 경계에서 다시 실행해 통과를 확인했습니다. 실제 마이크, 외부 STT, 외부 LLM 품질은 이 회귀 검증에서 실호출하지 않았으므로 별도 현장 검증으로 남습니다.

## 1. 1분 진단

1. 프런트와 Spring이 모두 떠 있는지 확인합니다.

   ```bash
   curl --fail --max-time 3 http://127.0.0.1:3100/
   curl --fail --max-time 3 http://127.0.0.1:8081/api/health
   ```

   Spring 정상 응답은 `status: UP`, `mode: service`입니다. `providerAvailability: not-probed`는 오류가 아니라 외부 AI나 전사 공급자를 헬스 요청에서 실호출하지 않았다는 뜻입니다.

2. 포트 충돌을 확인합니다.

   ```bash
   lsof -nP -iTCP:3100 -sTCP:LISTEN
   lsof -nP -iTCP:8081 -sTCP:LISTEN
   ```

   `127.0.0.1:8081`이 이 앱의 Spring 기본 주소입니다. `::1:8081`을 쓰는 다른 프로세스는 별개일 수 있으므로 PID를 확인하지 않고 종료하지 않습니다.

3. 첫 오류를 기준으로 보고 뒤의 파생 오류는 일단 보류합니다. `npm run dev`는 Spring과 Vite 중 하나가 종료되면 나머지도 정리합니다.

4. 재시작 전에 회의 화면의 `저장 전` 표시를 확인합니다. 저장하지 않은 전사는 새로고침과 프런트 재시작 시 사라질 수 있습니다.

## 2. 서비스가 안 뜨거나 로그인 화면만 나올 때

### 실행 준비

- Java 21+, Maven, Node.js 22.9+ 환경을 사용합니다.
- `apps/web` 의존성이 없으면 `npm --prefix apps/web install`을 실행합니다.
- `cp .env.service.example .env.service`로 로컬 설정을 만들고 필요한 값만 채웁니다. `.env.service`는 Git에 커밋하거나 채팅에 붙여 넣지 않습니다.

```bash
npm run dev
```

정상 기본값은 Vue `127.0.0.1:3100`, Spring `127.0.0.1:8081`입니다. `npm run preview`가 종료되는 것은 현재 서비스의 장애가 아닙니다. 프로덕션 미리보기는 아직 구성되지 않았고, 로컬 서비스는 `npm run dev`로 실행합니다.

### 401·403

- `401`: 세션이 없거나 만료됐습니다. 다시 로그인합니다.
- `403`: 팀 권한 또는 CSRF 토큰이 맞지 않을 수 있습니다. 새로고침하고 같은 `127.0.0.1:3100` 출처에서 다시 시도합니다.
- 브라우저에서 Spring `:8081`로 직접 API를 보내지 않고 Vite의 `/api` 프록시를 사용합니다. 세션 쿠키와 CSRF 토큰의 출처를 하나로 유지하기 위함입니다.
- HTTP 로컬 개발에서는 `COOKIE_SECURE=false`를 사용합니다. HTTPS 배포에서는 반대로 secure cookie를 켜야 합니다.

### 서버는 UP인데 화면이 로드되지 않음

1. 브라우저 콘솔의 첫 JavaScript 오류를 확인합니다.
2. Vite 터미널에 HMR 변환 오류가 있는지 확인합니다.
3. `npm --prefix apps/web run build`로 타입 오류와 프로덕션 빌드를 함께 검증합니다.
4. 로그인 화면으로 돌아가면 먼저 `/api/auth/me`의 `401`인지, 그 다음에 페이지 API의 `403/404/5xx`인지를 나눠 보아야 합니다.

## 3. DB·Flyway

- 로컬 기본 DB는 파일 H2이며 Git에서 제외됩니다. 운영 배포는 `DATABASE_URL`, `DATABASE_USER`, `DATABASE_PASSWORD`로 PostgreSQL을 명시적으로 구성합니다.
- Flyway는 Spring 시작 시 `V1`~현재 버전을 순서대로 적용합니다. 적용된 migration을 수정하지 말고, 스키마 변경은 다음 `Vn__description.sql`로 추가합니다.
- `checksum mismatch`가 나오면 DB를 바로 지우거나 `repair`로 덮지 않습니다. 기존 migration을 원래 내용으로 복구하고 새 migration을 만드는 것이 기본입니다.
- DB 락·포트·파일 오류가 나면 같은 DB를 사용하는 Spring이 두 개 떠 있지 않은지 먼저 확인합니다.
- 파일 DB 삭제는 로컬 계정·회의·저장 이력을 모두 잃는 작업입니다. 일회성 환경임을 확인하고 백업한 뒤에만 수행합니다.

## 4. 마이크·전사

### 스피커로 나오는 소리가 잡히지 않음

현재 기본 경로는 `getUserMedia`로 선택한 **마이크 입력**만 받습니다. 노트북 스피커, 화상 회의 앱, 다른 탭의 시스템 출력은 일반 마이크 권한으로 직접 캡처될 것을 보장할 수 없습니다.

- 스피커 울림 감소를 켜면 반대편 소리가 더 강하게 제거될 수 있습니다.
- 현재 제품 UI는 탭 오디오 공유 모듈을 실제 회의 흐름에 연결하지 않았습니다.
- 임의로 마이크로 자동 대체하거나 반대편 음성이 잡혔다고 표시하지 않습니다. 탭 오디오·가상 루프백·네이티브 캡처는 별도 기능과 사용자 동의가 필요합니다.

### 마이크 미터는 움직이는데 문장이 안 나옴

1. `마이크 테스트`와 `전사 시작`을 구분합니다. 테스트는 입력 크기만 보며 외부로 전송하지 않습니다.
2. 설정 화면의 공급자 상태를 확인합니다. `준비됨`은 키 형식·로컬 헬스 조건이며 실제 인증·잔액·한도·응답 성공을 의미하지 않습니다.
3. Groq·Azure·Deepgram 전송 동의를 공급자별로 다시 확인합니다. 한 공급자의 동의를 다른 공급자에 재사용하지 않습니다.
4. `전사 상태 확인`에서 입력 RMS, 포화 비율, 전송 대기, 요청 응답, 구간 분리 이유를 확인합니다. 이 수치는 정확도 점수가 아닙니다.
5. 오류로 중단된 미처리 음성은 복구되지 않습니다. 재시작하거나 `직접 입력`으로 보완합니다.

### 문장이 중간에서 자주 끊김

- 기본은 약 600ms의 쉼 또는 최대 4초에서 구간을 닫습니다.
- `문맥 유지 비교 · 최대 8초`를 쓰면 연속 발화 중 강제 분할을 줄일 수 있지만 첫 표시는 느려질 수 있습니다.
- 잡음 억제를 켜고 음절이 사라지면 같은 발화로 끄고 비교합니다. 설정 변경이 손실된 음성을 복원하는 것은 아닙니다.
- Groq를 쓸 때 `한국어 용어 인식 보조`를 켜면 최근 6개 문장과 직접 입력한 정확한 표기를 다음 음성 조각의 힌트로 보냅니다. 사후 LLM 보정이 아니므로 의미를 임의로 다시 쓰지 않습니다.
- 제품명·사람 이름을 `정확히 적을 용어`에 쉼표로 넣고 같은 발화로 켜짐/꺼짐을 비교합니다. 최근 대화도 Groq로 전송되므로 동의 문구의 범위를 확인합니다.

### 공급자별 확인

| 공급자 | 준비 조건 | 주요 확인 |
| --- | --- | --- |
| Groq | `STT_PROVIDER=groq`, `GROQ_API_KEY`, `GROQ_STT_MODEL` | 계정 플랜·요청 한도·429·실제 모델 사용 가능 여부 |
| Azure | `STT_PROVIDER=azure`, `AZURE_SPEECH_KEY`, `AZURE_SPEECH_REGION`, `AZURE_SPEECH_TIER=F0` | 키와 리전의 일치, 실제 리소스의 F0 여부 |
| Local | `STT_PROVIDER=local`, loopback `STT_LOCAL_URL` | `/health`와 `/inference`, 16kHz 모노 WAV 프로토콜 |
| Deepgram | `DEEPGRAM_API_KEY`, UI에서 Deepgram 명시 선택 | 30초 임시 토큰, WebSocket 연결, 계정·모델·언어 지원 |

어떤 경로도 실패 시 다른 업체로 자동 전환하지 않습니다. 세부 설정은 [클라우드 설정](cloud-setup.md)과 [전사 설정](speech-setup.md)을 보세요.

## 5. AI 확인·요약·맥락

### `설정됨`인데 AI 요청이 실패함

- `/api/llm/status`의 DeepSeek `configured=true`는 모델명과 키가 비어 있지 않다는 뜻입니다. 실제 인증, 잔액, 한도, 생성 성공은 동의 후 첫 요청으로만 확인할 수 있습니다.
- 로컬 모델은 `LLM_PROVIDER=local`, loopback `LLM_BASE_URL`, `LLM_MODEL`을 확인합니다. `/models`에 모델이 보여도 실제 생성 성공과는 다릅니다.
- DeepSeek 실패 시 로컬·다른 업체로 자동 전환하지 않습니다. 응답 오류를 그대로 진단합니다.
- `.env.service`를 바꿨으면 저장 전 회의를 먼저 보존하고 Spring을 재시작해야 합니다.

### 답변이 회의 맥락을 놓침

1. AI 패널의 `AI가 읽는 회의 흐름`에서 전체 문장 수, 주제, 결정·변경 신호가 잡혔는지 봅니다. 이 브리프는 LLM 없이 계산하므로 갱신 자체에는 토큰이 들지 않습니다.
2. `회의 근거만`은 원문·선택한 팀 자료 밖의 일반 지식을 막습니다. `회의 + 일반 지식`은 회의 근거와 모델의 일반 지식을 서로 다른 영역으로 표시하며 외부 웹 검색은 하지 않습니다.
3. `핵심 원문`은 빠른 확인, `넓은 원문`은 변경 흐름과 더 많은 증거가 필요한 질문에 사용합니다. 전체 흐름 브리프는 두 모드 모두 함께 전달됩니다.
4. 질문의 단어가 회의에서 쓰인 용어와 한두 글자 다르면 검색 후보를 함께 사용하고 화면에 `원문 → 후보`를 표시합니다. 원본 질문은 바꾸지 않으며 의미가 달라질 가능성은 확인 필요로 남깁니다.
5. 회의 근거, 일반 지식, 확인 필요, 남길 내용 추천을 따로 읽습니다. 추천은 원문 ID가 있는 결정·할 일·미결 이슈만 만들며 자동 저장하지 않습니다.
6. 의미 기반 임베딩·장기 메모리·여러 회의 검색·실시간 웹 검색은 아직 아닙니다. 현재는 토큰 없는 전체 브리프와 질문별 관련 원문을 결합합니다.

### 중간 맥락 브리프가 갱신되지 않음

- 기본은 실질 문장 8개가 추가될 때마다 갱신합니다. 대화가 뜸하거나 새 문장이 없으면 호출하지 않습니다.
- `필요할 때만`을 선택했다면 `지금 갱신`을 눌러야 합니다.
- 브리프 실패가 AI 질문 실패를 뜻하지는 않습니다. 질문 요청 시 서버가 같은 브리프를 다시 만들고, 관련 원문을 별도로 검증합니다.

### 요약이 비어 있거나 예전 내용만 보임

- 현재 요약 요청은 저장된 버전과 화면의 저장 전 전사 스냅샷을 함께 보냅니다. `저장 전 변경사항까지 이번 요약에만 포함`이 보이는지 확인합니다.
- 요약은 회의 원문을 자동 저장하거나 합의로 확정하지 않습니다.
- 빈 전사, 모델 미설정, 외부 전송 미동의, 권한 오류를 각각 나눠 확인합니다.

### 토큰 수치가 예상과 다름

- 사용량 페이지는 공급자가 token usage를 반환하면 `실측`, 그렇지 않으면 문자 수 기반 `추정`으로 표시합니다.
- 이 원장은 요청·입력·출력 토큰 수만 저장하며 프롬프트, 회의 원문, 답변은 저장하지 않습니다.
- 공급자 콘솔과 차이가 나면 기간, 계정, 재시도, 스트리밍·비스트리밍 집계 범위를 먼저 맞춥니다. 현재 화면은 비용을 추정하지 않습니다.

## 6. 회의 화면·저장·삭제

### 최신 대화를 따라가지 않음

- `최신 대화 따라가기`가 체크되어 있을 때만 새 확정 문장으로 이동합니다.
- 사용자가 이전 대화를 읽으러 위로 스크롤하면 체크가 자동으로 풀리고, 새 확정 문장 수를 표시합니다.
- 다시 체크하거나 `새 문장 n개 보기`를 누르면 최신 문장으로 즉시 이동하고 새 대화를 계속 따라갑니다.

### 저장하지 않은 내용이 사라짐

- `저장 전` 표시는 현재 브라우저에만 있는 변경을 뜻합니다. `기록 저장` 후 `기록 저장됨`을 확인합니다.
- 이동 경고에서 `저장하고 나가기`는 원문 확인 체크와 전사 중지가 필요합니다. AI 초안·직접 입력 중인 내용은 별도로 확인합니다.
- 서버 재시작, Vite HMR, 새로고침을 테스트하기 전에 항상 저장 상태를 봅니다.

### 회의를 잘못 삭제함

회의 목록의 휴지통 아이콘은 바로 영구 삭제하지 않고 회의를 휴지통으로 옮깁니다. `휴지통 보기`에서 복구합니다. 보존 기간 후 자동 영구 삭제는 아직 구현되지 않았습니다.

## 7. 검증 명령

가장 작은 범위부터 실행하고 전체 검증으로 넓힙니다.

```bash
# Vue 단위 테스트
npm --prefix apps/web test

# Vue 타입 검사 + 프로덕션 빌드
npm --prefix apps/web run build

# Spring 테스트
mvn -q -f apps/server/pom.xml test

# 서비스 전체
npm test
npm run build:service

# 공백·충돌 마커 확인
git diff --check
```

외부 STT·LLM 키가 없는 환경의 통합 테스트 성공은 실제 음성 인식·잔액·요청 한도·응답 품질을 인증하지 않습니다.
